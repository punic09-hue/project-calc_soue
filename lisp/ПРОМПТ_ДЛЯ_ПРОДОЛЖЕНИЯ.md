## Состав архива

- `src_utf8/` — те же исходники в UTF-8 (правим их, потом конвертируем: `iconv -f utf-8 -t cp1251 X_utf8.lsp > X.lsp`).
- `doc/manual.js` — генератор руководства (Node.js, библиотека `docx`): `node manual.js` → `Руководство_LISP.docx`.

## Постоянные правила (обязательно)
1. В начале каждого lsp — **шапка со списком команд и инструкцией**; при загрузке тот же список печатается в командную строку.
2. Файлы для AutoCAD — **cp1251**; проверять кодировку и читаемость (символы вне cp1251 нельзя: вместо Σ ² Ø пишем Sum, 2, %%c). После правки — **проверка баланса скобок** (скрипт, учитывающий строки и комментарии).
3. Все команды с префиксом **БЛОК_**, объявляются трижды: строчными, ПРОПИСНЫМИ и латиницей (например `c:мм_кабель`, `c:ММ_КАБЕЛЬ`, `c:MM_CABLE`).
4. **Руководство_LISP.docx обновлять при каждом изменении lsp** (содержание, все инструкции, глава со стандартными командами/переменными AutoCAD, история изменений — новая строка с датой).
5. Использовать наработки, не ломать уже сделанное; отвечать по-русски, кратко; файлы отдавать сразу (lsp в cp1251 + docx).
6. DCL пишется во временный файл; кодировка по LISPSYS (>0 — UTF-8 BOM, иначе ANSI). Подписи кнопок — только в DCL. Заголовки колонок — отдельный list_box с теми же tabs. Во всех таблицах на чертеже выравнивание — середина по центру.
7. Длины кабелей везде (окна, таблицы, CSV, спецификация, с запасом и без) — **вверх до целого метра**.
8. CSV: utf8-bom, разделитель `;`, числа с запятой, похожие на даты тексты как `="текст"`, имя с датой-временем, вопрос о замене.
9. Все выноски — **в общей рамке, без подчёркивания, с маскировкой фона**, отступ рамки = 0.5 высоты текста, линия выноски без полки в угол рамки. Таблицы на чертеже — с маскировкой фона (WIPEOUT под таблицей).

## Концепция кабеля (blok_kabel.lsp) — текущее состояние
- Кабель = **безымянная группа** полилиний-участков; XDATA приложения "BK" в виде `ключ=значение`.
  Ключи: `id marka diam pos floor beg end ld layer lts bcode bk ecode ek bfix efix bh eh bmd emd md tmd sz code h k tcode tk ord`.
- Участок (parts): `(code h pts k ename tcode tk look md tmd sz)`; строка расчёта: `(вид название высота длина коэф код №участка с_запасом d_материала размер)`.
- Длина = участки × коэф. + опуски к приборам (атрибут ВЫСОТА блока или вручную) + переходы по высоте. Приборы у концов ищутся автоматически (радиус 200 мм) или привязываются вручную.
- **Трасс больше нет** (понятие убрано по моему решению). Прокладка задаётся:
  - при создании кабеля — поле «В чём прокладывается» (по умолчанию «в гофр. трубе»);
  - в окне свойств по строкам (прокладка, диаметр материала, высота, коэф.);
  - **ММ_КАБЕЛЬ_УЧАСТОК** — щелчок по отрезку между вершинами ([Точки] — часть отрезка): находятся **все наложенные кабели** на участке, окно с их сечениями, суммой сечений и диаметром пучка D = K(n)·√(Σd²/n); для лотка/короба — размер Ш×В, допустимое заполнение и расчёт заполнения группы; для труб — требуемый dвн; OK применяет ко всем кабелям участка.
- Учёт способов в спецификации (режим типа): **O** — общий для группы (лоток, короб, трос: наложенные участки считаются один раз, по размеру «Лоток 100x50»), **E** — свой материал у каждого кабеля (гофра, трубы, металлорукав, по диаметру d20…), **N** — не считать (открыто).
- Диаметр материала активен для всех способов, кроме лотков/коробов; по умолчанию гофра/труба 20, металлорукав 15, труба в полу 25.
- Способы прокладки (со строчной буквы): в гофр. трубе (Тг), в лотке (Л), в кабель-канале (К), в трубе жёсткой (Т), в трубе в полу (П), в металлорукаве (Мр), в гофр. трубе скрыто в штробе (штриховая), на тросе (Тр), на тросе в гофр. трубе (ТрГ), открыто (сплошная). Хранятся в чертеже (ldata "BK" "types"), правятся в ММ_КАБЕЛЬ_ТИПЫ; старые чертежи мигрируют автоматически.
- **ММ_КАБЕЛЬ_ЛИНИИ** — [Типы/Сплошная/Штриховая]: рисовать без обозначения типов, способы сохраняются (ldata "BK" "plain").
- Выноски: **ММ_КАБЕЛЬ_ВЫНОСКА** (строки «ПОЗИЦИИ — марка» + нижняя строка «в чём прокладывается» в точке выноски), **ММ_КАБЕЛЬ_ВЫНОСКА_ПРОКЛ** (способ, «Ø расч.» / «Ø расч. общий (n каб.)», заполнение %), **ММ_КАБЕЛЬ_ВЫНОСКА_ПАРАМ**, **ММ_КАБЕЛЬ_ОБНОВИТЬ** [Авто] — реактор :vlr-commandEnded автообновляет выноски.
- **ММ_КАБЕЛЬ_СВОЙСТВА** — окно кабеля (откуда/куда, **помещения начала и конца из атрибута ПОМЕЩЕНИЕ**, таблица строк, привязка к блокам). **ММ_КАБЕЛЬ_ВСЕ** — все кабели: поиск/сортировка (в т.ч. по помещениям), итоги, выгрузка таблицы кабелей и спецификации в CSV/на чертёж. **ММ_КАБЕЛЬ_ЖУРНАЛ**, **ММ_КАБЕЛЬ_ЛЕГЕНДА**, **ММ_КАБЕЛЬ_ИЗ_ЛИНИИ**, **ММ_КАБЕЛЬ_ПЕРЕСОБРАТЬ**, **ММ_КАБЕЛЬ_ЕЩЕ** (ещё кабель по пути выбранного).
- Выбор наложенных кабелей: щелчок → если несколько, окно-список; [Рамка] — обычный выбор.

- Справочник кабелей (29.09.2026): внешний `cable_type.csv` в папке чертежа (тип;оболочка;проводник;номенклатура;сечение;диаметр_мм, UTF-8 BOM или cp1251), хранится в ldata "BK" "cat", кнопка «Обновить»/ММ_КАБЕЛЬ_СПРАВОЧНИК — слияние без дублей по номенклатуре; поле marka кабеля = номенклатура; в окнах зависимые фильтры Тип/Оболочка/Проводник/Сечение → Номенклатура; ручной ввод, если файла нет.
- Формат выносок (ММ_КАБЕЛЬ_ВЫНОСКА_ФОРМАТ): шаблоны с полями {ПОЗ} {НОМ} {ТИП} {ОБОЛ} {ПРОВ} {СЕЧ} {D} {ЭТАЖ} {ОТКУДА} {КУДА} {ПОМ1} {ПОМ2} {ДЛИНА}, нижняя строка {ПРОКЛ}, выноска прокладки {ПРОКЛ} {DРАСЧ} {ОБЩ} {N} {SUMS} {ЗАП}; ldata "BK" "ldfmt"; по OK обновляются все выноски.

- Стояки (29.09.2026): способ STOYAK «стояк» (штриховая, слой _СТОЯК цвет 51 непечатаемый, DRAWORDER назад, длина по умолчанию 5 м); у участка ключи slen (длина вручную), sflm (этаж вручную), sfl (этаж авто), у кабеля floors (этажи через запятую), floor — этаж по умолчанию; parts: индексы 11 slen, 12 sflm, 13 sfl; авто-этаж — bk:floors по блокам-стоякам у концов участков «стояк», иначе откуда/куда.

- Трубы (29.09.2026): md — номинальный диаметр, заполнение по внутреннему (*bk:dint*, bk:din, bk:tube-fill, bk:tube-pick); колонка «Зап., %» в окне свойств; в спецификации расшифровка по кабелям. ММ_КАБЕЛЬ_ВЫНОСКА_СТОЯК (MM_CABLE_LEADER_RISER): 2 выноски у концов участка-стояка, XDATA "BK_ST", нижняя строка — шаблоны 7/8 в ldfmt (9 элементов).

- ММ_КАБЕЛЬ_ЭЛ (29.09.2026): потери напряжения; ключи кабеля et eu ei ep ecos edu esec emat, у участка sp (мощность участка, Вт); формулы DC/AC1/AC3, rho Cu 0.0175 Al 0.028; окно как ВСЕ, «!!» для превышения, двойной щелчок — участки с нарастающими потерями, экспорт CSV/чертёж (кабели и по участкам). Длина кабеля bk:total = сумма по способам, каждая вверх до 1 м (журнал «Итого» = сумма колонок). Справочник читается только по «Обновить». Значок у диаметра (image dstat) — заполнение труб.

- ММ_КАБЕЛЬ_ТРАССИРОВКА (переделана 30.09.2026): пользователь указывает блок начала, блок конца и щелчком кабель-трассу (или Нет); кабель идёт по отрезкам этого кабеля (bk:tr-edges, bk:tr-near-edge, bk:tr-sub) между точками, ближайшими к блокам, подводки GOFRA d20 Г-образно (bk:tr-conn). Можно несколько трасс по порядку (переход в ближайших точках, bk:tr-closest), вопрос «Трасса существующая?». Отметка участка «сущ. трасса» — ключ "ex" (parts индекс 14, строка расчёта индекс 11): материал не идёт в спецификацию. Автоматический поиск по сети кабелей (Дейкстра) убран — пользователь счёл результат неправильным. Имя переменной t запрещено (константа T). В AutoLISP нет EQL, PROG1, WHEN, LET, DOLIST и т.п. — не использовать.
